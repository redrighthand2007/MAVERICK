B.1What an “agent” is

An agent is a program that takes a request and does one kind of job. In MAVERICK each agent is a plain Python class, not ChatGPT. The files agent copies, moves, renames and measures files. The process agent looks at running programs. That's it.

The word “agent” sounds magical. In MAVERICK it means: a worker with a clear job description and the same set of buttons as every other worker.

AnalogyA hospital. Reception (the orchestrator) listens to you and sends you to the right specialist (an agent): the eye doctor, the dentist. Each specialist has the same routine: hear the problem, find the details, check it's safe, treat, write a report.
RememberAgent = one job + the same shape as all the others (parse, extract, describe, handle).

B.2Multi-agent design

One orchestrator (the manager) and many sub-agents (the workers). The manager never does the work itself. It only decides who should do it, passes the request on, and handles the things every request has in common: help, exit, missing details, errors, y/n questions.

Why not one giant program?Adding a feature would mean editing the giant program. Here, a new agent = a new folder + one line in main.py.
Why the same shape?The manager can treat every worker the same way. It never needs to know how a worker does its job.
Why one manager?The shared rules (safety, confirmation, error messages) live in one place, so no agent can forget them.
RememberManager decides who. Worker decides how. Shared rules live with the manager.

Function

A named, reusable piece of work. Input goes in (parameters), output comes out (return).

# maverick/core/units.py — the whole file
def human_size(num_bytes: int) -> str:
    size = float(num_bytes)
    for unit in ("B", "KB", "MB", "GB", "TB"):
        if size < 1024 or unit == "TB":
            return f"{size:.0f} {unit}" if unit == "B" else f"{size:.2f} {unit}"
        size /= 1024

human_size(5_368_709_120) → "5.00 GB". Divide by 1024 until the number is small enough.

Type hints

num_bytes: int and -> str are notes for humans and tools: “expects an int, returns a string”. Python doesn't enforce them. Intent | None means “an Intent, or nothing”.

Class, object, inheritance

A class is a blueprint; an object is one thing built from it. Inheritance means “start from this blueprint and change some parts”. Every agent inherits from SubAgent:

class FileAgent(SubAgent):      # "a FileAgent IS a SubAgent"
    name = "files"              # class attribute: same for every FileAgent
    risky = {"move", "rename"}

    def __init__(self, tagger=None):   # runs when you create one: FileAgent(tagger)
        self.tagger = tagger             # instance attribute: this object's own value

    def parse(self, text): ...      # overrides SubAgent.parse

Override = a child class replaces a method of its parent. SubAgent.is_risky() says “risky if the operation is in risky”; the process agent overrides it because “show frozen apps” is safe but “end frozen apps” is not.

Dataclass

@dataclass writes the boring __init__ for you. Used for the two shapes everything passes around:

@dataclass
class Intent:
    operation: str
    args: dict = field(default_factory=dict)   # a NEW empty dict per Intent
    missing: list[str] = field(default_factory=list)
CarefulWhy field(default_factory=dict) and not args: dict = {}? A plain {} default would be one shared dict for every Intent ever made: change it in one place, it changes everywhere. default_factory builds a fresh one each time.

Module, package, import

A module is one .py file. A package is a folder of modules with an __init__.py. from maverick.core.safety import SafetyError means: go to folder maverick/core/, open safety.py, take the name SafetyError. python -m maverick.brain.train runs a module as a program, which is why the training scripts end in if __name__ == "__main__": main().

Exceptions

An exception is “stop, something is wrong” thrown up the call chain until someone catches it. MAVERICK defines its own, SafetyError, raised by any safety check. The orchestrator catches it in safely() and turns it into a polite Blocked for safety: ... message. Nothing is touched because the error happens before the action.

try:
    return action()
except SafetyError as exc:
    return Result(False, f"Blocked for safety: {exc}")
except OSError as exc:          # Windows itself said no (locked file, no permission)
    return Result(False, f"Windows refused the operation: {exc}")

Lambda

A tiny nameless function. self.safely(lambda: agent.handle(intent)) passes “the work, not yet done” so safely() can run it inside its try.

Regular expressions (regex)

A mini-language for patterns in text. r"[a-z0-9]+" = “one or more lowercase letters or digits”. MAVERICK uses regex for keyword rules, path detection (PATH_LIKE_RE) and pronouns (PRONOUN_RE finds “it” / “them”).

pathlib.Path

A path as an object instead of a string. Path("D:/x") / "a.txt" joins paths; .exists(), .is_dir(), .parent, .name, .resolve() (make absolute and clean up ..) are used all over safety.py.

L.1Classification

Classification = putting an input into one of a fixed set of boxes (labels). MAVERICK's brain sorts a sentence into one of 42 labels: 41 operations like files.copy, process.end, hardware.ram, plus unknown (“nothing MAVERICK can do”).

A label is written agent.operation. The orchestrator splits it at the dot: "files.copy".split(".", 1) → ["files", "copy"], so it knows the agent and the operation.

The model learns from labelled examples: pairs of (label, sentence) written by hand in maverick/brain/data/intents.tsv (1,374 of them, ~30–40 per label). This is supervised learning: someone supervised it by giving the right answers.

files.copy      copy notes.txt to D:\backup
process.end     kill chrome
hardware.ram    how much ram do i have
unknown         book me a flight to paris
CarefulREADME and RESULTS.md say “46 operations”. Counting the actual file gives 41 operations + unknown = 42 labels (1,374 sentences). Trust the file; the docs number is stale.
Why an “unknown” label?Without it, the model must pick a real operation even for “tell me a joke”. With 71 “unknown” examples it can say “none of these”.
RememberClassification = sentence → one label from a fixed list. 42 labels (41 operations + unknown), written agent.operation. Learned from 1,374 hand-labelled sentences.

L.2Tokens and bag of words

Computers can't read. They count. First a sentence is cut into tokens (words) by tokenize() in brain/text.py:

tokenize('copy notes.txt to D:\\backup')
→ ["copy", "<path>", "to", "<path>"]
  1. Anything in quotes becomes <path>.
  2. Each piece is stripped of ?!.,; at the end.
  3. If it looks like a path (has a slash, starts with D:, or ends in .txt-style extension) → <path>.
  4. Otherwise it's lowercased, apostrophes removed, and split into letter/digit runs.
Why replace paths?File names say nothing about which operation you want. “copy budget.xlsx” and “copy cat.jpg” are the same request. Hiding the name stops the model from learning silly things like “.jpg means copy”.

A bag of words then forgets order and just counts: {"copy":1, "<path>":2, "to":1}. Like tipping the words into a bag and shaking it.

CarefulA bag can't tell “what started chrome” from “what did chrome start” (same words, opposite meaning: parent vs children). That weakness is exactly what Stage 8.1 (word pairs) fixes.
Remembertokenize = lowercase words, paths → <path>. Bag of words = counts, no order.

L.3TF-IDF

Not all words are equally useful. “the” appears everywhere and tells you nothing; “rename” is rare and tells you almost everything. TF-IDF gives each word a weight:

  • TF (term frequency): how many times the word is in this sentence.
  • IDF (inverse document frequency): how rare it is across all sentences. MAVERICK uses idf = log((1+n)/(1+df)) + 1, where n = number of sentences and df = how many contain the word.
  • weight = TF × IDF. Then each sentence's numbers are scaled to length 1, so long and short sentences compare fairly.
WordIn how many of 1,000 sentencesIDF (roughly)Meaning
to4001.9Common, weak signal
rename304.5Rare, strong signal

Code: TfidfVectorizer in maverick/brain/features.py (Stage 8.1).

RememberTF-IDF = how often here × how rare everywhere. Rare, telling words weigh more.

L.4Train / test split and accuracy

To grade a model honestly, never test it on sentences it learned from. That would be like giving students the exam questions as homework.

  • Training set: the model learns from these.
  • Test set: the model never sees these until grading.
  • Accuracy = right answers ÷ total answers.
  • Stratified split (dataset.split()): every label keeps the same share in train and test, so a rare label isn't missing from the test.
  • Hard cases (hard_cases.tsv, 84 sentences): deliberately tricky wordings that are never trained on. The “final exam”.

Stage 8.6 upgrades this to 5-fold cross-validation: one split swung between 75% and 86% depending on luck.

RememberTrain on some, test on the rest, never mix. Accuracy = right ÷ total. Hard cases = the never-trained final exam.

L.5Overfitting

Overfitting = memorising the training sentences instead of learning the pattern. The model scores 100% on training data and badly on new data. The opposite, underfitting, means the model is too simple to learn even the training data.

AnalogyA student who memorises last year's answers word for word fails when the teacher changes one number. A student who learned the method passes.

How MAVERICK fights it:

  • L2 regularisation (logistic regression, SVM, MLP): a small penalty on big weights, so no single word dominates.
  • Dropout (MLP): randomly switch off 30% of neurons while training.
  • Smoothing (Naive Bayes): pretend every word was seen a little, so an unseen word doesn't zero everything.
  • Cross-validation + hard cases: measure on data the model never saw.
  • Freezing MiniLM: only a small layer learns, so 1,374 sentences can't overfit 22.7M numbers.
RememberOverfitting = memorising, not learning. Fight it with L2, dropout, smoothing, and honest testing.

L.6Confidence, softmax and the cut-off

Every brain returns (label, confidence). Confidence is a probability between 0 and 1: “how sure am I?”.

Softmax: scores → probabilities

A model first gives each label a raw score (any number). Softmax turns scores into probabilities that add up to 1: p_i = e^(score_i) / Σ e^(score_j). Bigger score → much bigger share, because of the exponential.

scores:  files.copy 4.0   files.move 2.0   unknown 0.0
e^score:          54.6              7.4            1.0     (sum 63.0)
softmax:          0.87              0.12           0.02

Code trick: subtract the biggest score first (scores - scores.max()). The answer is identical but e^1000 would overflow.

The cut-off (threshold)

If confidence ≥ the brain's threshold, the orchestrator trusts the brain. Below it, MAVERICK falls back to keyword rules. Between 0.5 and the threshold, if nobody understands, it suggests: “Did you want files.copy? Try rephrasing.”

BrainCut-offWhy that value
Naive Bayes0.6Its confidences run high
Logistic regression / SVM / MLP0.4Probability spread over ~40 labels
Ensemble0.3Averaging lowers confidences
MiniLM (current)0.3Sweep: 0.3 gave 91.6% / hard 86%
CarefulEach cut-off was chosen by measuring (a “sweep”: try 0.2, 0.3, 0.4, 0.5 and keep the best), not guessed. The model carries its own threshold; CONFIDENCE_THRESHOLD = 0.6 in the orchestrator is only the fallback.
RememberSoftmax turns scores into probabilities. Confident (≥ cut-off) → trust the brain; else → keyword rules. MiniLM's cut-off is 0.3.

L.6bLogs, probabilities and gradient descent (the maths atoms)

Why logarithms?

Multiplying many small probabilities (0.01 × 0.02 × 0.005 …) quickly becomes a number too small for a computer (“underflow”). Logs turn multiplication into addition: log(a×b) = log a + log b. So Naive Bayes adds log-probabilities instead of multiplying probabilities. Same winner, no underflow.

Loss

A loss measures how wrong the model is. MAVERICK's models use cross-entropy: loss = −log(probability given to the right label). Right label at 0.9 → loss 0.1 (small). At 0.01 → loss 4.6 (big). “How surprised was the model by the truth?”

Gradient descent

The model has weights (numbers). The gradient says, for every weight, “which way and how steeply does the loss change if I nudge you?”. Gradient descent repeats: compute the loss, nudge every weight a little downhill. Learning rate = step size. Epoch = one pass over all training data.

AnalogyWalking down a foggy hill: you can't see the valley, but you can feel which way the ground slopes under your feet. Take a small step that way. Repeat 800 times.

Momentum (used in MAVERICK's logistic regression): keep 90% of the last step's direction, so learning “rolls” through flat stretches faster. Adam (used in the MLP): a step size per weight that adapts itself.

Vector, matrix, dot product, cosine

  • Vector: a list of numbers. A sentence after TF-IDF, or MiniLM's 384 numbers.
  • Matrix: a table of numbers. All sentences stacked = one matrix x.
  • Dot product x @ weights: multiply matching numbers and add. One line computes every label's score for every sentence.
  • Cosine similarity: the angle between two vectors. 1 = same direction (same meaning), 0 = unrelated. Used by k-NN, GloVe and MiniLM.
RememberLogs turn × into +. Loss = how surprised by the truth. Gradient descent = small downhill steps. Cosine = how similar in meaning.

1.1Vision and design rules

docs/VISION.md

MAVERICK is an offline AI assistant for Windows: plain-English requests, a central agent that routes them, specialist agents that act safely in Python. No internet, no cloud, no API keys. It grew out of a single-purpose Linux course project (a smart archive agent).

The six design rules

  1. Every agent has the same shape (parse, extract, handle, plus risky and describe). New agent = one folder + one line in main.py.
  2. Understanding is separate from doing. agent.py only reads text; ops.py only acts.
  3. AI decides what, never whether it's allowed.
  4. Safe by default. Never overwrite · never system folders or whole drives · delete only to the Recycle Bin · never stop core Windows services · fixed argument lists, user names quoted · passwords at a hidden prompt, never logged.
  5. Measured, not guessed. A new model replaces the old one only if it scores higher on the same 5-fold cross-validation. Failures are written down too.
  6. Testable without side effects. Every system call sits behind a small function the tests replace with a fake.
RememberSame shape · read≠do · AI proposes · safe by default · measured · fakeable. (S-R-A-S-M-F: “Six Rules Always Save My Files”.)

1.3The orchestrator

maverick/core/orchestrator.py (155 lines)

The central agent. It holds the list of agents, a lookup by_name, the brain, the splitter, the LLM tool caller, and three pieces of memory: pending (a risky action waiting for y/n), queue (pieces of a multi-action request still to run) and done (what earlier pieces reported).

handle(text): the front door

  1. Forget any unanswered question and queue (a new request drops them).
  2. Empty → “Please type a request.” · exit/quit/bye/goodbye → Result with {"exit": True} · help → list agents.
  3. Ask the splitter for pieces. If several: guess each one, and only if every piece is understood, run the first and queue the rest (chain). Otherwise treat the whole text as one request.
  4. handle_one(text).

handle_one(text): the decision ladder

run(agent, intent) and confirm(yes)

def run(self, agent, intent):
    if intent.missing:
        return Result(False, f"[{agent.name}] I need: " + ", ".join(intent.missing))
    if agent.is_risky(intent):
        # describe() runs the safety checks first, so a blocked action is never even asked about.
        question = self.safely(lambda: Result(False, agent.describe(intent), {"confirm": True}))
        if question.data.get("confirm"):
            self.pending = (agent, intent)
        return question
    return self.safely(lambda: agent.handle(intent))

safely() wraps every call: SafetyError → “Blocked for safety: …”, OSError → “Windows refused the operation: …”. The program never crashes on a bad request.

RememberLadder: brain → keywords → LLM → polite give-up. run(): missing? risky? do. Every call goes through safely().

build() and why agent ORDER matters

Keyword rules ask agents one by one; the first that says “mine” wins. So order encodes tie-breaks:

ProcessJobsWatchLogsServicesNetworkDevicesAccountsPowerCleanupHardwareSearchArchiveFiles
  • Watch before files: “move every new pdf in downloads to documents” is a watcher, not a one-off move.
  • Logs before cleanup and archive: “compress server.log” rotates a log, it doesn't zip it.
  • Process before hardware: “which programs use the most memory” is about programs, not RAM size.
  • Power before hardware: “turn on battery saver” is a mode, not a battery reading.
  • Cleanup before hardware: “free up space on D:” wants space back, not a number.
  • Search before files and archive: “find big files”, “find zip files” are searches.
  • Files last: its words (“size”, “big”, “copy”) are the most generic.

ask_if_needed(): if a Result has data["confirm"], ask (y/n). Only y or yes runs it; anything else (even Enter or Ctrl+C) cancels.

RememberThree modes: chat · one-shot · --background. In build() the specific agents come first, generic Files last, because the first keyword match wins.

1.6Tests

tests/ (34 files, 490 tests) · pytest.ini · tests/conftest.py

A test sets something up, runs real MAVERICK code, and asserts the outcome. Example from tests/test_confirm.py:

def test_move_asks_first_and_changes_nothing(tmp_path):
    src = make_file(tmp_path)                       # a real file in a throwaway folder
    result = build().handle(f'move "{src}" to "{tmp_path / "b.txt"}"')

Key ideas

  • Fixture: something pytest prepares for a test. tmp_path is a fresh empty folder, deleted afterwards.
  • monkeypatch / fakes: replace a real system call with a pretend one. Killing processes, changing services, power modes: all faked, so the suite never changes your PC.
  • autouse fixture in conftest.py: every test gets its own disk-history file, so fake drive readings never land in your real ~/.maverick/disk_history.tsv.
  • Accuracy floor: test_brain.py fails if the brain's accuracy drops below a minimum. A test that guards a model.

2.7Naive Bayes, from scratch

maverick/brain/naive_bayes.py (73 lines)

The idea in one line

score(label) = log P(label) + Σ log P(word | label). The label with the highest score wins.

  • P(label), the prior: how common the label is. 40 of 1,374 sentences are files.copy → 0.029.
  • P(word | label), the likelihood: of all words in files.copy sentences, what share is “duplicate”?
  • Naive = it pretends words are independent of each other. Wrong, but works surprisingly well.

Training = just counting

def fit(self, examples):
    for label, tokens in examples:
        self.label_counts[label] += 1                          # sentences per label
        self.word_counts.setdefault(label, Counter()).update(tokens)  # words per label
        self.vocab.update(tokens)                             # every word ever seen

A tiny worked example

Pretend training data: copy sentences contain the word “duplicate” 3 times in 50 words; move sentences 0 times in 50 words. Vocabulary: 100 words.

Laplace smoothing (+1 on every count, so 0 never happens):
P("duplicate" | copy) = (3 + 1) / (50 + 100) = 0.027
P("duplicate" | move) = (0 + 1) / (50 + 100) = 0.0067
→ "duplicate" makes copy 4× more likely than move.

Unknown words (not in vocab) are skipped: they say nothing. Finally softmax turns the log-scores into probabilities (subtracting the max first).

CarefulWithout smoothing, one word never seen with a label gives probability 0, and log(0) = −∞: that label can never win again, whatever else the sentence says.
RememberNaive Bayes = count words per label, score = log prior + sum of log word-likelihoods, +1 smoothing, softmax. No training loop at all.

8.1N-grams + TF-IDF

maverick/brain/features.py

N-grams: besides single words (unigrams), also count word pairs (bigrams), so order shows up. <s> and </s> mark the start and end, so “kill …” differs from “… kill”.

ngrams(["what", "started", "chrome"])
→ what, started, chrome, <s>_what, what_started, started_chrome, chrome_</s>
ngrams(["what", "did", "chrome", "start"])
→ ..., did_chrome, chrome_start, ...        # different pairs → different meaning

Then TF-IDF (atom L.3) weights each feature, and each row is scaled to length 1.

Result: didn't help Naive Bayes (74% → 71%): NB counts “started” and “started_chrome” as independent evidence, so the same clue counts twice. It paid off in 8.2, where logistic regression learns weights instead.

RememberWord pairs capture order. Same features can hurt one model (NB double-counts) and help another (LR learns weights).

8.2Logistic regression (softmax regression)

maverick/brain/logistic_regression.py (93 lines)

Naive Bayes counts. Logistic regression learns one weight per (feature, label) by gradient descent.

score(label)  = Σ weight[feature, label] × feature value + bias[label]
probabilities = softmax(scores)
loss          = −log(probability of the right label)
repeat 800×:  nudge every weight downhill

The training loop, line by line

probs  = softmax(x @ self.weights + self.bias)     # predictions for ALL sentences at once
error  = (probs - y) / len(examples)               # y = one-hot truth; error = how far off
grad_w = x.T @ error + self.l2 * self.weights      # gradient, plus L2 to keep weights small
velocity_w = 0.9 * velocity_w - lr * grad_w         # momentum: keep 90% of the last step
self.weights += velocity_w
  • One-hot: the truth as a row of 0s with a single 1 in the right label's column.
  • probs − y is the gradient of cross-entropy loss w.r.t. the scores (a famously neat result).
  • Settings by cross-validation (8.8): 800 epochs, learning rate 4.0, L2 = 1e-5, threshold 0.4.

Result: hard cases 60% → 76%. Overlapping features (“started”, “started_chrome”) no longer double-count: the model learns how much each adds.

RememberLR = weights × features → softmax → cross-entropy → gradient descent (+ momentum, + L2). Learns, doesn't count.

8.5Ensemble / soft voting

maverick/brain/ensemble.py · members: logistic regression + Bernoulli NB + linear SVM

Several models answer; their probabilities are averaged (“soft” voting: a confident model counts more than a hesitant one; “hard” voting would only count each one's top pick).

Why it worksDifferent models make different mistakes. LR weighs words and pairs; Bernoulli NB hears what's missing; the SVM only cares about borderline sentences. When one is wrong, the other two often outvote it. Three copies of the same model would just repeat the same mistakes.

Result: 84.5%, hard 75%, threshold 0.3 (averaging lowers confidences). Since MiniLM shipped, the ensemble is the fallback brain: used automatically on a PC without the MiniLM files (and in CI).

RememberEnsemble = average the probabilities of LR + Bernoulli NB + SVM. Works because they disagree on different sentences. Today's fallback brain.

8.6Cross-validation

dataset.folds() · evaluate.cross_validate()

Split the data into 5 equal, stratified buckets. Five rounds: train on four, test on the fifth. Every sentence is tested exactly once. Report the average. A fixed seed (42) makes it repeatable.

Why: one 80/20 split swung between 75% and 86% depending on which sentences happened to land in the test. 5-fold is stable.

Remember5 buckets, 5 rounds, each sentence tested once, average the scores. Fixes “lucky split”.

8.8Hyperparameter tuning

Parameters are what a model learns (weights). Hyperparameters are settings you choose before training: epochs, learning rate, L2, smoothing, threshold, number of neighbours, hidden size.

MAVERICK picks them by cross-validation sweeps: try several values, keep the one with the best 5-fold score. Never by looking at the hard cases (that would be studying the final exam).

8.9Neural brain (MLP)

maverick/brain/mlp.py (116 lines, NumPy only)

  • Neuron: weighted sum of inputs, then ReLU (max(0, x): negatives become 0). Hidden neurons learn their own in-between ideas (“this is about files”, “this is a question”).
  • Backpropagation: run forward, measure loss, pass the error backwards layer by layer (chain rule) to get every weight's gradient.
  • Mini-batches of 32 + Adam optimiser (step size per weight). Dropout 30% against overfitting. 40 epochs.

Result: a tie with LR (79.5% vs 79.4%) at 4× the training time. With ~1,200 sentences, a deeper model has little extra to learn. Kept as an option.

RememberMLP = input → hidden (128, ReLU, dropout) → output (softmax); trained by backprop + Adam. Tied LR: more power needs more data.

8.10Word embeddings (GloVe)

maverick/brain/embeddings.py · GloVe 6B 50d (171 MB, offline)

Every model so far treats words as unrelated IDs: “copy” and “duplicate” are as different as “copy” and “banana”. An embedding gives each word a list of numbers (here 50) learned from billions of words of text, so words used the same way end up close together.

  • Try 1, synonym swap: replace an unknown word with its nearest known word. Failed (79.0% vs 78.9%): in GloVe's 50 dimensions “duplicate” sits next to “categorize”, not “copy”.
  • Try 2, meaning features: add the sentence's average word vector to the TF-IDF numbers: 84.0%. Not used at runtime.
RememberEmbedding = word → numbers of meaning. Word-level GloVe wasn't enough; whole-sentence meaning (8.11) was.

8.11Sentence embedding model: MiniLM (the current brain)

maverick/llm/encoder.py (experiment) · maverick/brain/minilm.py (shipped)

all-MiniLM-L6-v2: a small pretrained transformer (22.7M numbers, 90 MB). It reads the whole sentence, every word looking at every other word (attention), and outputs 384 numbers for the sentence. It was trained on a billion sentence pairs to put sentences that mean the same close together, even with no word in common.

  • Frozen: nothing inside MiniLM changes. Only VectorLR (logistic regression on 384 dense numbers, 400 epochs) learns. Training takes seconds on a CPU.
  • Pooling: MiniLM gives one vector per word piece; average them (ignoring padding) and scale to length 1 → one sentence vector.
  • Cache: sentences already embedded are remembered (up to 20,000) since loading and running costs time.
  • Transfer learning: reuse knowledge learned on a huge task (sentence similarity) for a small one (your 41 operations).

Result: 91.6% as MAVERICK runs, hard 86% (threshold 0.3), up from 84.5% / 75%.

RememberMiniLM turns a sentence into 384 numbers of meaning; frozen; our small LR on top is the only learner. 91.6% / hard 86%.

8.15Slot filling (BIO tags + Viterbi)

maverick/brain/slots.py · data slots.tsv · used by the files agent's extract()

The brain answers “what?” (files.copy). Slot filling answers “with what?”. Every word gets a tag: this is sequence labelling.

copymythesistotheusbdriveF:\
OOB-sourceOOOOB-destination
  • B- = beginning of an argument · I- = inside (continues it) · O = outside (not an argument).
  • Features per word: the word, its neighbours (2 each side), its shape (drive / slashed / file / quoted / number / word), the operation, “have we seen to yet?”.
  • Softmax regression (same maths as 8.2) scores every tag for every word.
  • Viterbi picks the best sequence of tags and forbids broken ones (an I-source right after O). It keeps, for each word and each tag, the best score of any sequence ending there, plus a back-pointer; then walks back from the end.
  • slots limits tags to the operation's arguments (rename has no destination).

Result: 93.0% of sentences fully right vs 79.0% for the regex (which took “can”, “you”, “pls” as file names).

RememberTag every word B/I/O · softmax per word · Viterbi = best valid sequence. 93% vs 79%.

8.16Several actions in one sentence (splitter)

maverick/brain/multi.py · data multi.tsv · orchestrator chain() + fill_in()

“copy notes.txt to D:\backup and zip it” is two requests. “cut and paste notes.txt” is one. So is “cpu name and cores”. A rule “split at every and” breaks those, so the splitter learns.

  1. Candidates: every gap before and / then / also / plus, or after a comma.
  2. Features per gap: the connector, words around it, how many words on each side, is there a path on each side, is there “it/them” on the right.
  3. Stacking: the intent brain reads each side too and says what action it is and how sure. “end them” is clearly process.end; “all its windows” is nothing alone. Those answers become features.
  4. A logistic regression (8.2, reused) answers cut / keep: binary classification.

Then the orchestrator

  • Every piece must be understood before the first one runs; otherwise treat it as one request.
  • chain() runs pieces in order. A failed piece stops the rest (“Stopped there, so I did not: …”). A y/n question pauses the chain until you answer.
  • fill_in(): “it” / “them” in the next piece becomes the previous piece's data["output"], in quotes: zip it → zip "D:\backup\notes.txt".

Result: 95.8% of multi-action sentences cut right; 89.2% of one-action sentences with an “and” left whole.

RememberCandidate gaps → features + brain's opinion of each side (stacking) → cut/keep. All pieces understood first; “it” = previous output.

8.17Local LLM setup (Ollama)

maverick/llm/ollama.py

An LLM (large language model) predicts the next word, over and over, to write text. Ollama runs one on your own PC as a small web server at http://localhost:11434, loading Llama 3.2 3B (~2 GB) onto the graphics card. “localhost” = this computer: nothing leaves the PC.

  • One question = one HTTP POST to /api/chat with messages: system (how to behave), user (the question), and optionally earlier assistant answers.
  • temperature 0 = always pick the most likely next word, so the same question gets the same answer.
  • Standard library only (urllib + json). Every failure becomes LLMError, so MAVERICK just works without it.

~38 tokens/s, 0.7 s per short answer on the RTX 2050.

RememberOllama = local LLM server on localhost:11434 · Llama 3.2 3B · POST /api/chat · temperature 0 · failures → LLMError → skip it.

8.20LoRA fine-tune

maverick/llm/lora.py · SmolLM2-360M-Instruct

Prompting tells a model; fine-tuning teaches it (the knowledge ends up in its weights). Full fine-tuning of 360M numbers doesn't fit a 4 GB card. LoRA (Low-Rank Adaptation) freezes them all and adds small trainable matrices next to the attention layers:

W x   becomes   W x + B (A x)      W: 960×960 frozen · A: 16×960 · B: 960×16 (trained)
B starts at zero → before training, behaves exactly like the original.

Only ~0.9% of the numbers train; the adapter is a few MB. Predicting: score every real label (“how likely is Action: <label>?”) instead of letting it write freely.

Result: 81.5% vs the brain's 82.7% on the same split, 250 ms per sentence. Not used.

RememberLoRA = freeze the big matrix, train a tiny B·A beside it. Worked, but didn't beat the brain.

8.21LLM agent loop

maverick/llm/loop.py · AgentLoop (used in main.py when Ollama is running)

Some requests need one step's answer to choose the next: “how big is notes.txt, and zip it if it's over 1 MB”, “which is bigger, D:\a or D:\b?”. So the conversation continues: model → action → MAVERICK runs it → “Result: …” → model → next action or done.

Safety stays with MAVERICK

  • Every action goes through check() and the orchestrator's run().
  • A risky action ends the loop: its y/n question goes to you, never to the model.
  • A failed step ends it. At most 4 steps. The same action twice ends it (small models go in circles).
  • Values may come from the request or an earlier result: “zip the biggest one” can only name a file a result actually showed.
RememberThe core of every “AI agent”: a model in a loop with tools. Think → check+act → observe → repeat (max 4) → done. Model never answers a y/n.

8.22Anomaly detection (isolation forest)

maverick/brain/anomaly.py · used by “any unusual programs running?” (process.unusual)

Unsupervised: no labels; nobody can label “this program behaves strangely”. The model only sees the data and finds what doesn't look like the rest.

Idea: pick a random column and a random cut point; repeat inside each side until every point sits alone. A normal program sits in a crowd and needs many cuts; an odd one is cut off after a few. Shorter path = more unusual. 100 random trees, each on ≤ 256 points, vote: score = 2^(−average path / c(n)); ≈ 0.5 or less normal, near 1 unusual (MAVERICK flags ≥ 0.55 with a reason).

Features (log scale, per copy): RAM, RAM growth (only growth counts), CPU, threads, handles per thread, network connections.

Result: 3 planted fakes among 113 real programs ranked 3rd, 5th, 6th (vs ~57th sorted by RAM).

RememberIsolation forest: odd points are isolated by fewer random cuts. Unsupervised. Fakes ranked 3, 5, 6 of 113.

8.23Clustering (k-means)

maverick/brain/cluster.py · used by “group the files in my downloads” (search.group)

  1. File names → words (Invoice_March-2024.pdf → invoice, march, ext:pdf, kind:document) → TF-IDF numbers.
  2. Pick k starting centres, spread out (k-means++).
  3. Give every file to its nearest centre; move every centre to the average of its files; repeat until nothing changes. Several restarts, keep the tightest.
  4. Choose k with the silhouette score: (b − a) / max(a, b), a = distance to own group, b = to nearest other group. Near 1 = clearly in the right group.

Result: 96.8% pair agreement vs 94.9% grouping by extension.

Rememberk-means: assign to nearest centre ↔ move centre to average, repeat. k chosen by silhouette.

8.24Regression / forecasting

maverick/brain/forecast.py · used by “when will C: be full” (hardware.forecast)

Classification predicts a category; regression predicts a number. Fit the straight line used = intercept + slope × day with least squares (smallest sum of squared misses). Exact formula, no training loop:

slope     = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)²
intercept = ȳ − slope × x̄

Then follow the line until it reaches the drive's size. Honesty checks: R² (how much of the up-and-down the line explains) and a slope range (± 2 standard errors). Caveat: a line assumes you keep using the disk like you did lately.

Result: off by 2.1 GB vs 7.3 GB (“no change”) and 35.5 GB (“repeat yesterday”).

RememberRegression = predict a number. Least-squares line through disk history, R² + uncertainty, needs ≥ 3 readings.

8.25Ranking (learning to rank)

maverick/brain/rank.py · used by search results

Ranking puts things in order. Each found file → 9 features: exact name, starts with query, whole words, name coverage, recent, own folder, junk folder, depth, user file type. score = Σ w × feature.

Pairwise learning (like RankNet): for every search we know the meant file; every other file gives a pair, and we want score(meant) > score(other). P = sigmoid(difference), pushed towards 1 by gradient descent.

MRR (mean reciprocal rank): meant file at place 1 → 1, place 2 → ½, place 5 → ⅕; averaged. Result: 0.718 vs 0.571 hand-set, 0.422 newest first, 0.339 disk order.

Honest limitTrained on made-up searches built on assumptions. Logging which result you actually open would be the real data.
Remember9 features · learned weights from pairs (meant beats other) · graded by MRR 0.718.

A goal request: you say what you want in the end, not which files. Each candidate has a benefit (GB freed) and a regret (0 = temp junk … 1 = last week's photos). Find the set that frees at least the goal with the least total regret: a knapsack problem.

8.27Constraint solving

maverick/brain/constraints.py · used by “plan maintenance between 10 pm and 2 am” (jobs.plan)

A CSP has variables (when each job starts), domains (every 15-minute slot that leaves room to finish) and constraints (disk-heavy jobs never overlap · at most 2 at once · clear temp before the junk scan). No score: it fits or it doesn't.

  • Backtracking: assign one job, go on; when a rule breaks, undo the last choice and try the next slot.
  • MRV (most constrained first): decide the job with the fewest slots left first.
  • Forward checking: after each choice, cross out slots it rules out for others; if any job has none left, back up at once.

Result: 509 choices vs 141,885 (~280× fewer). MRV alone was worse than plain backtracking. It only plans; it doesn't start jobs (the task scheduler was skipped).

RememberCSP = variables + domains + constraints. Backtracking + MRV + forward checking = 280× fewer tries.

Glossary A–Z

Active learningThe model chooses what to ask a human about: its least confident cases first.
AdamGradient descent with a self-adjusting step size per weight.
AgentA worker with one job and a standard shape.
AttentionInside a transformer: every word looks at every other word to build its meaning.
BackpropagationPassing the error backwards through a network to get every weight's gradient.
BacktrackingTry a choice; if a rule breaks later, undo it and try the next.
Bag of wordsWord counts, order ignored.
BaselineThe simple method a model must beat (here: keyword rules).
BIO tagsBegin / Inside / Outside labels for each word of a sentence.
CITests run automatically on a fresh machine for every PR.
ClassificationInput → one label from a fixed list.
ClusteringGrouping similar things without labels.
ConfidenceThe probability the model gives its own answer.
Confusion matrixTable of real label vs predicted label; off-diagonal cells are mistakes.
Cosine similarityHow closely two vectors point the same way (1 = same meaning).
Cross-entropyLoss = −log(probability of the right answer).
Cross-validationk rounds of train-on-most, test-on-rest; average.
CSPConstraint satisfaction problem: variables, domains, rules.
ctypesPython's way to call Windows' C functions directly.
DataclassA class whose __init__ Python writes for you.
DropoutRandomly switching neurons off while training, against overfitting.
Dynamic programmingSolve a big problem by building up answers to smaller ones (knapsack).
EmbeddingA word or sentence as a list of numbers that captures meaning.
EnsembleSeveral models vote; here soft voting (average probabilities).
EpochOne pass over all training data.
F1Harmonic mean of precision and recall.
Few-shotShowing an LLM worked examples in the prompt.
Fine-tuningFurther training a pretrained model on your own data.
FixtureSomething pytest prepares for a test (e.g. tmp_path).
Forward checkingAfter each choice, remove values it rules out for others.
Gradient descentRepeatedly nudge weights in the direction that lowers the loss.
GroundingChecking an LLM's values really appear in the user's text or a result.
HandleWindows' ticket for an open file, key, thread or event.
Hard casesTricky sentences never trained on: the final exam.
Hinge lossSVM's loss: zero once the right label wins by a margin.
HyperparameterA setting you choose (epochs, learning rate), not learned.
IntentMAVERICK's “what you want”: operation + args + missing.
Isolation forestAnomaly detector: odd points are isolated by fewer random cuts.
k-meansClustering: assign to nearest centre, move centres, repeat.
k-NNLabel by majority vote of the k most similar examples.
KnapsackPick items under a constraint to minimise cost / maximise value.
L2Penalty on large weights; keeps a model from memorising.
Laplace smoothing+1 (or +α) on every count so nothing is ever probability 0.
Learning rateSize of each gradient-descent step.
LLMLarge language model: predicts the next word repeatedly.
LockLets only one thread at a time touch shared data.
LoRAFine-tune by training tiny B·A matrices beside frozen weights.
LossA number measuring how wrong the model is.
Macro F1F1 averaged over labels, each label counting equally.
MomentumKeep part of the last step's direction while descending.
MRRMean reciprocal rank: 1 / position of the right answer, averaged.
MRVMost-constrained-variable-first heuristic in CSP search.
N-gramA run of n words; bigrams = word pairs.
Naive BayesClassifier from word counts assuming words are independent.
One-hotA row of 0s with a single 1 marking the right label.
ONNXPortable file format for a trained model; run by onnxruntime.
OrchestratorThe manager agent that routes requests and applies shared rules.
OverfittingMemorising training data instead of learning the pattern.
PrecisionOf the answers given as X, the share that were really X.
PRPull request: a proposal to merge a branch, reviewable on GitHub.
RecallOf the real X's, the share the model found.
RegressionPredicting a number (vs a category).
ReLUmax(0, x): the activation in MAVERICK's MLP.
ResultMAVERICK's “what happened”: success + message + data.
Sequence labellingOne label per word instead of one per sentence.
SilhouetteHow well a point fits its own cluster vs the nearest other.
Slot fillingFinding the argument values in a sentence.
SoftmaxTurns scores into probabilities summing to 1.
StackingOne model's predictions used as features for another.
StratifiedSplit that keeps each label's share the same in every part.
Supervised / unsupervisedLearning from labelled examples / from data alone.
SVMSupport vector machine: wins by a margin; borderline cases matter.
TemperatureLLM randomness; 0 = always the most likely word.
TF-IDFHow often here × how rare everywhere.
ThreadA second line of work running inside the same program.
TokenA piece of text a model works with (a word, or a word piece).
Tool callingAn LLM choosing an action from a menu and returning it as JSON.
Transfer learningReusing a model trained on a big task for a small one.
TransformerNeural network built on attention (MiniLM, Llama).
ViterbiFinds the highest-scoring valid sequence of tags.
Zip SlipAn archive entry whose path escapes the extraction folder.

The whole project in ten sentences

  1. MAVERICK is an offline Windows assistant: you type English, it acts on your PC, nothing leaves the machine.
  2. One orchestrator routes each request to one of 14 agents that all share the same shape.
  3. Each agent splits understanding (agent.py) from doing (ops.py).
  4. A trained brain (MiniLM + logistic regression, 91.6%) guesses agent.operation; if unsure, keyword rules decide; if nobody understands, a local LLM proposes a checked action.
  5. A slot tagger finds the arguments and a splitter cuts multi-action sentences; “it” means the last result.
  6. Safety checks run before anything happens; risky actions ask y/n and check again after “yes”.
  7. Nothing is ever overwritten, deleted permanently, or done inside system folders.
  8. A background thread runs saved jobs like folder watchers and log rotators.
  9. Thirty AI methods were built from scratch and kept only when they measurably beat the previous one.
  10. Every system call is faked in 490 tests, and every smart part has a simpler fallback.
